## 2. `5e0fc80` — the cold-start fix (3 parts + CTA), all in `src/windows/review/`
- **B. Land on a document.** New PURE `decideInitialSelection({targetId,queueGrouped,queue,groups})`
  (in `renderer.js`, just above `loadQueue`, closed by a `/* __PIN_END:decideInitialSelection__ */`
  marker the test extracts on): grouped view with a **SINGLE** sender pile (the cold-DB/single-sender
  case) auto-expands it + opens the first doc; **2+ piles → land on nothing** (keep the deliberate
  all-collapsed overview); flat "Newest first" unchanged (top row). `loadQueue` now reads
  `getReviewTarget()` FIRST, then chooses **navigate XOR select**.
- **C. Race fix (free).** The old code fired an un-awaited `selectDoc(queue[0])` AND then a second
  `selectDoc` for an "Edit in Review" target → last-writer-wins double-select on `currentDoc`/
  `pageImages`. The XOR restructure removes it.
- **A. Relabel the "—" pile (display only).** `groupTitle(supplier, groupCount)`: the null pile reads
  **"Your scanned documents"** when it stands alone / **"Sender not identified"** among named piles;
  per-row null → **"Not yet identified"**. The group **KEY stays `'—'`** (expand-state + ↑/↓ nav
  depend on it — Oracle **C4**). The unidentified pile is sunk in the **shared** `reviewDisplayGroups()`
  sort (**C1** — so list and nav stay in lockstep), but **below** the attention (`need>0`) term so a
  flagged unidentified batch is never buried under a clean named pile (**C2**).
- **Empty-pane CTA** (`index.html` `#preview-cta` + `renderer.js`): for the returning-user 2+-pile
  case, a "Ready when you are … Start reviewing →" card replaces a dead pane; the button lands on the
  first doc in the visible order. Hidden via the SINGLE `_clearPreviewState` seam the instant a doc is
  selected or the panel clears. Reuses themed `.btn.primary`. `refreshAutoCommittedBar()` kept (**C3**).

## 3. `f4463cd` — mid-session advance
The **Defer** button (`renderer.js` ~:4536) and the **File-All done-path** (~:4310) used the same
