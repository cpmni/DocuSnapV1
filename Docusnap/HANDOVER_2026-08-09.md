## The FAILED fix (`TEMPLATE_FORMAT_FAIL_YIELD`) — why it failed + the redesign
Design (gary→Oracle SIGN-OFF-W/COND): a taught read that FAILS its field format yields to a confident
format-PASSING disagreeing keyword read. Helper legs: L1 method endswith `_shapewarn`; L2
`template_mapper._format_rejects` (learned shape); L3 strict currency (leading-glyph + `parse_amount`, so
`£-662.18`/continental/swiss PASS, `L922.14` FAILS). Floor 88 (Oracle C1). Carve-out mirrors `_blind_reg`.

**GATE FAILED on NEW corpus (TEACH, new_ffy vs new_teach):** po_ref **+0.0** (never fired), total **+0.9**
(marginal), **ref −1.0 (REGRESSED)**. The 3 regressed refs: the carve-out swapped CORRECT-but-shapewarn'd
taught refs → GARBAGE keyword reads ("The", "25-07-2025", "Tel 01632 964956 VAT Reg No…").

**Two flaws (root-caused):**
1. **A shapewarn ≠ a wrong value.** L1 trusts the `_shapewarn` tag, but a CORRECT value gets shapewarn'd when
   the learned shape is thin → the carve-out fires on correct taught reads. AND the "keyword passes format"
   check is too weak — garbage "The" passed it → swap adopted garbage. That is the ref regression.
2. **po_ref 0-fire is NOT the conf floor** (VERIFIED: a "Your PO" keyword read is **conf 93** ≥ 88). The
   blocker is elsewhere — see OPEN LEADS.

**REDESIGN (clear):** judge BOTH the taught read AND the keyword challenger by the field's **HARD validation
pattern** (the config `validation_patterns` regex keyword itself validates against, keyword.py:1036-1041) —
NOT the shapewarn tag, NOT only the learned shape. That (a) rejects garbage keyword "The"/"Tel…" → no ref
regression; (b) catches "Account" (fails po-code pattern) → po_ref can fire; (c) PASSES a correct-but-shapewarn'd
read → no false-fire. Drop L1 (shapewarn) + relax/remove the conf floor (the hard pattern is the quality gate).
Keep L3 (currency). Then re-gate.
