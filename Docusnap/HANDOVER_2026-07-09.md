## 2. The fix that ships (durable, reusable, reversible)

**Filing-critical per-field confidence floor** — `database/modules/trust.js` `isAutoFileEligible`.
A PRESENT reference/date value (the type's `ref_field_key`/`date_field_key`) must itself clear
`critical_field_conf_floor` (default **88**, setting-tunable, `0`=off) to auto-file, at EVERY floor
including 100 (overall is a blended average that can sit above a weak critical field — e.g. logo@98 +
date@98 lifting a ref@87 to overall 100). It only ever **HOLDS a doc for Review**; it can never cause a
wrong auto-file.
- **Why 88 (reggie-calibrated):** must be above the bleed (reprocesses at conf 87) but not above the
  by-design `base_confidence` of a clean critical read (config: 90 for invoice_number, 88 for
  invoice_date). 90 would over-hold clean base-88 date reads (real-world usability regression); 88
  catches the 87 bleed and lets clean base reads through.
- **Guarded** by `database/modules/test_scope_trust.js` section 15b (all pass).

### Measured impact (harness, live DB, 1206 confirmed docs)
| Config | regressions | would-auto-file-WRONG | note |
|---|---|---|---|
| `main` (shipped) | 46 | **25** | 24× City Office `1828987` bleed + #404 |
| branch + **floor**, anchor STILL in DB | 46 | **1** | only #404 (poisoned GT — pipeline correct) |
| branch + floor + anchor removed (in-mem) | **26** | 5 | ALL 5 are poisoned GT (pipeline correct — see below); ref acc 96.3%→**97.9%** |

**Key reading:** the harness scores against CONFIRMED values, some of which are poisoned. Every single
"would-auto-file-wrong" in the fixed configs is a doc the pipeline reads CORRECTLY against a wrong stored
answer — #404 (`22162`/`03-06-2026`, per its own OCR+filename); #896/#897/#916/#1026 (`152567` — the real
City Office number — vs GT `1/2`); #962/#1012 (`337729`/`337728` vs GT `102`). That is exactly why
removing the anchor makes the metric rise 1→5: the pipeline now confidently produces the RIGHT value,
which the poisoned GT counts as "wrong." **Genuine silent-wrong-auto-file risk = 0.** The remaining ~18
`null [flagged]` reads are hard low-quality Anconia docs, safely routed to Review (never silently filed).

**The code fix ALONE (data NOT cleaned) takes would-auto-file-wrong 25 → 1.** Cleaning the anchor
restores the correct READS (regressions 46→26, all residual = poisoned GT + safely-flagged nulls).
