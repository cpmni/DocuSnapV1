against the live DB:** the generic Stage-1 date patterns in `keyword_patterns.json` all carry a bare

`delivery_date` lacks bare `"Date"`, so it comes from its learned anchor (which garbled on doc #7).
Incidence: **20/81 delivery notes**. **No current confidence loop consumes cross-date agreement** (checked
engine/anchor/validator) — but the po_date-corroboration backlog item would, so this is a latent trap.
**Recommended fix layer: Option A** — persist/learn only the doc-type's own fields at the storage/confirm
seam (lowest blast radius; corpus gate is blind to it, so the gate must be a JS/DB test). Options B
(type-scope the Stage-1 match) and C (kill the bare-`"Date"` bleed) are higher-blast extraction changes.
**Owner + Oracle choose before building.**
