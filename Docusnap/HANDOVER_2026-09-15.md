## What was built (newest first; every commit pushed)
### A. Simpler-connection feature (design `docs/designs/SIMPLER_CLIENT_CONNECTION_2026-09-14.md`; Oracle log 2026-09-14)
The design vet is the important context: **you cannot win the first-hello trust bootstrap on the wire** — three
owner ideas (broadcast the fingerprint / a second verification port / an encrypted-DB fingerprint / a date-time
handshake code) were each REJECTED with the reason recorded in the design's "settled principle" (same network =
same attacker; the app isn't a secret so a shared algorithm authenticates nothing). The only real anchors are
**off-network** (QR/short code off the server SCREEN, or a profile FILE) or **pre-shared** (a pairing code a human
carries) + **pin-after-accept**. Do NOT re-litigate — point the owner at that section.
- **S1 `7ee1341` (server):** pairing-code WRITER (`client-api-pairing-{generate,clear,status}`; `_genPairingCode`
  = ≥8 UNAMBIGUOUS alnum, no 0/O/1/I/L; pinned `src/modules/api/test_pairing_code.js`); a QR generated in MAIN
  (`client-api-connect-qr`, `qrcode` MIT new core dep) of `{host,port,tls,fingerprint,code}` ONLY — NEVER the CA
  PEM; the Settings **"Connect a client" card** (address + one-time code with countdown + QR + the stable-address
  tip); the enable toggle gated on host+port (UI-only, C5). THIRD-PARTY-LICENSES regenerated for qrcode.
- **S2 `6ebe66a`+`7aa3a62` (client):** `client/lib/certVerify.js` = the PURE trust decisions
  (normFp/computeFingerprint/verifyExpected/isCertError/isAltNameError/classifyCertChange), pinned by
  `client/lib/test_cert_verify.js` (T1/T2). `client/main.js`: `client-connect-verified` + `client-connect-accept`
  — MAIN fetches the CA, computes the fingerprint, compares to the QR/profile's expected value, and pins **the
  exact bytes MAIN fetched**; the CA PEM never round-trips through the renderer (C1/C2). `isCertError` routed
  BEFORE `isNetworkError`; `handleCertError` re-fetches + `classifyCertChange` → same CA = 'addr-mismatch' (a SAN
  gap, no re-pin) vs different CA = 'changed' (stash + `client-cert-alert`, the ONLY re-pin path is an explicit
  human accept) (C3). Renderer: a styled accept modal (refuse-is-default, replaces `window.confirm`), the
  cert-change re-accept modal, import-profile pins in MAIN.
- **S3 `7e657b0` (client):** the client scans the QR (`Scan a QR code…` button = pick an image; or Ctrl+V paste on
  the connect screen). `jsQR` (Apache-2.0, vendored to `client/renderer/vendor/jsQR.js` — force-added, `vendor/` is
  gitignored; loaded under CSP 'self'); decode in the renderer → `connectVerified` auto-verifies the fingerprint +
  pins in MAIN. `client-pick-qr-image` reads the image in main.
- **`716e846`:** `run-pins` now discovers `client/lib` so the connection security pins run in `test:pins`.
- ⚠ **Owed at the next CLIENT build:** add `jsqr` to `client/THIRD-PARTY-LICENSES.txt` (Apache-2.0, allowlisted).
