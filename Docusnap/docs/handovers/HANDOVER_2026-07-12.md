### `2ba919f` — Wrong-supplier logo collision (Cascade⇄Thornbury) — the priority fix
**Root cause (verified in code + live DB):** the two suppliers' monogram logos (TF/CW) collide in the coarse
top-left greyscale phash (cross-supplier Hamming 8–14, threshold 13), AND Cascade's `logo_fingerprints` set
was POISONED with TF prints from past misfiles (learned on each auto-file confirm via `saveLogoFingerprint`,
no identity check). So the logo path resolves Cascade *decisively* (defeating the existing ambiguity guard),
the template path picks the wrong same-logo sibling without consulting branding, and `identity_fusion` is
inert in packaged builds (rapidfuzz unbundled) + its "established" bypass trusts poisoned-Cascade. 14 docs
mislabelled (all Thornbury→Cascade); 6+ confirmed/auto-filed.

**Files:** `python_backend/extraction/engine.py` (`_flag_branding_conflict` + `_BRANDING_STOPWORDS`),
`database/modules/learning.js` (`saveLogoFingerprint` cross-plant guard), `python_backend/tests/test_branding_conflict.py` (NEW),
`database/modules/test_logo_crossplant_guard.js` (NEW), `stress_test/gt_overrides.json` (+7 Thornbury entries),
`docs/oracle_log.md` (case 5).

**Mechanism:** at the engine finalisation seam (AFTER the identity-conflict block, skipped if that block
already acted), if the RESOLVED supplier's own template keyword-fingerprint is essentially absent from the
page (`own_ratio ≤ 0.25`, ≥3 distinctive words), cap `supplier_name` ≤69 + review note (names the
branding-detected alternative) + `needs_review`. **FLAG-ONLY — value never changed; the NOTE is what blocks
auto-file** (`trust.isAutoFileEligible` refuses any non-empty validation_note; the cap alone does NOT block
at overall==100). Exemptions: `method=='manual'` + `resolved ∈ accepted_issuers` ONLY. Kill switch
`BRANDING_CONFLICT_GUARD` (default ON). Save-guard: refuse to plant a NEW phash under X when it's decisively
closer to a different supplier's print; first-ever print always planted; manual bypass; UPDATE branch untouched.

**`_BRANDING_STOPWORDS` — found DURING the A/B, not in Oracle's original design.** The first A/B caught the
REVERSE direction (#1/#42 = genuine Cascade docs read as Thornbury, SILENT): Thornbury's fingerprint is
polluted with generic doc-type words (`DELIVERY`/`DOCKET`/`Delivery`) that also print on a Cascade DELIVERY
DOCKET → `own_ratio`(Thornbury on Cascade page)=0.30 > 0.25 → no flag. Fix strips a doc-type stopword set so
the check judges on DISTINCTIVE company/address tokens only. Symmetric + fail-safe (can't add a false flag).
Took M 3→1. Pinned by the `CASCADE_DOCKET` test case.

**Oracle: SIGN OFF WITH CONDITIONS (all 4 applied)** — (1) exempt only manual+accepted_issuers, NOT
template_fixed_locked/keyword_override (the closed hole — the template path stamps template_fixed_locked);
(2) placement after the identity block + skip if it acted (dodge stale-var false-flag) + preserve/append an
existing note; (3) trigger = own-branding-absent, not collision-gated; (4) save-guard first-print bootstrap +
manual bypass + UPDATE untouched. Oracle also traced that the **note (not the cap) is the load-bearing
auto-file block** (trust.js:443). Oracle now 5-for-5 (`docs/oracle_log.md`).

**Advisors:** oscar (logo/phash — recommended branding text over any hash tweak; flagged that the existing
