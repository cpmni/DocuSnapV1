### `6d72833` — buyer-issued issuer guard (built by the PRIOR session, committed now)
- **Root cause:** on a Purchase Order the letterhead is the BUYER (issuer); the body prints
  "Supplier:/Vendor:/Seller:" (the vendor). `supplier_name`'s label bank matched those captions, so on a
  cold-start DB the Document Issuer filled with the VENDOR @40 — and the value drives the filing/learning
  SCOPE (engine.py:2259), so a careless confirm would file + learn the logo under the wrong company.
- **Fix:** `engine._suppress_buyer_seller_issuer` DROPS a `supplier_name` keyword read whose matched label is
  a seller caption on a buyer-issued type (ref role `po_number` OR trusted `purchase_order` title), unless
  operator-allowlisted. Issuer then falls to logo/letterhead/hint or empty→review like every other type.
  Oracle conditions C1–C5 applied (2.5a re-adopt guard, `_ref_key` hoist, allowlist exempt, buyer-issued
  detection). Kill switch `BUYER_ISSUED_ISSUER_GUARD`.
- **Files:** `python_backend/extraction/engine.py`, `python_backend/process_docs.py`,
  `docs/oracle_log.md`, `python_backend/tests/test_buyer_issued_issuer_guard.py` (new).
- **Verified:** own test green (34 checks); 118 script-style Python tests pass incl. all identity/caption
  neighbours; the 5 suite failures are PRE-EXISTING (identical on pristine HEAD — stash-verified). The
  `ref_field_key` param insert is caller-safe (every `engine.extract` caller passes `supplier_name`+ by
  keyword). Oracle log now 6-for-6.

### `1eceb9e` — A: surface the import refusal (main renderer)
- **Root cause:** `process-folder` refuses some imports up front (source ⊆ output/Processed folder, licence,
  setup error) by RESOLVING `{success:false, error}` — not throwing — so `startProcessing()`'s try/catch
  never saw it and fell through to "✓ 0 processed" with no explanation.
- **Fix:** `startProcessing()` checks `processResult.success === false && processResult.error`, shows the
  reason + opens the collapsed log. Gated on `error` present so a normal batch / partial worker-exit failure
  still renders results.
- **File:** `src/windows/main/renderer.js`. Verified: `node -c` clean; logic traced against the handler's
  return shapes (normal completion returns `{success,stopped}` with no `error`).
