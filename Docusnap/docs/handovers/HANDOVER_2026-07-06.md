## 1. DONE — cross-supplier positional anchor bleed (the #1 known bug) → 2fa79b8

**Status: FIXED + committed (2fa79b8); 007-reviewed (verdict MODIFY, all adjustments folded in); A/B

The design record is below; the shipped shape matches "Proposed change" exactly. REMAINING = the
false-locate RESIDUAL + positional offset-elevation (see the end of this section).

**Bug (all confirmed in `python_backend/extraction/anchor.py`):** an authoritative ⊕ anchor for a
POSITIONAL field (e.g. Anconia's `invoice_number`, pinned top-right) bleeds onto a different
supplier's same-type doc (City Office invoice) and blind-reads at the taught absolute position →
locks the wrong region.
1. `_anchor_matches` (anchor.py:2064) admits cross-supplier on doc-type match (line 2104).
2. `_filter_anchors` (anchor.py:1991) `auth_bucket` (line 2016) ranks any ⊕ teach ahead of supplier-priority.
3. `_is_blind_cross_supplier_identity` (anchor.py:2034) is IDENTITY-ONLY (line 2047) — positional never dropped.

**Two findings that shaped the design:**
- **(a) `located_ok` already IS the "same layout?" signal.** At anchor.py:789-807, for an
  authoritative rigid read `located_ok` = "did the taught label actually appear on this page?"
  (runs `_locate_for_relocation`). Same layout → label found → kept; different layout → label
  absent → blind. So the handover's old "only trust cross-supplier when a TEMPLATE matched" is
  SUBSUMED — no new template signal needed. The just-landed label_box fix (§2) makes this locate
  more reliable.
- **(b) M=0 is already protected here.** A blind read is hard-capped at conf≤50 (anchor.py:809) →
  the field flags for review → it can't silently auto-file (corpus is M=0 before & after). So the
  bug is NOT a silent-wrong-file hole — it's a plausible-WRONG positional value SURFACED in Review
  (hand-confirmable) when no other method fires. Real, but lower severity than "silent file".

**Proposed change (minimal):** generalise `_is_blind_cross_supplier_identity` →
`_is_blind_cross_supplier_anchor`: drop a blind (`not located_ok`) read from a NAMED different
supplier for ANY field, keeping the identity-only display-name-artifact branch; EXCLUDE
`__global__`/`__unknown__` (drop only a named different supplier — conservative, targets exactly the
Anconia→City Office class). One function generalised + the call site at anchor.py:814/817-818
(name + reject reason). Reuses the existing `continue` drop (line 818). A LOCATED read is still kept
(the "authoritative wins" invariant holds — only blind cross-supplier reads drop, exactly as identity
already does). Passive anchors are unaffected (`located_ok=True` for passive, line 794) → blast radius
= authoritative anchors only.

**Open questions posed to 007** (its answers decide the final shape): DROP vs DISCOUNT+flag for
positional (given M=0 already protected); does `located_ok` truly subsume template-scoping or does a
FALSE-locate need a value/shape check; ALL-fields vs positional-only (date/ref are "pattern-trusted");
exempt `__global__`; guard PASSIVE too or authoritative-only; is read-stage the right layer vs
admission/precedence; exact A/B + test assertions.

**A/B gate (required before commit):** `stress_test/realdoc_regression.js` must stay **M=0 AND show no
per-field accuracy drop** (dropping a blind cross-supplier read could regress a doc where it was the
only correct signal — 007 flagged over-dropping regressed the corpus for identity). Plus stage-
attribution. Tests: extend `python_backend/tests/test_identity_anchor_scope.py` with positional
cross-supplier cases (blind → dropped; LOCATED → kept; same-supplier blind → kept; global → kept).

**ANCHOR-DRIFT THREAD — COMPLETE.** The false-locate residual is now fully closed across all field
types: FREE-TEXT/CURRENCY via the LABEL LOCK, REF + inline DATE via the authoritative-crop cross-check
(8a4bff5), and the value-BELOW-label sliver via the flag-only geometric detector (79868d4, see §2). Key
insight from tracing: the original "elevate `_place_from_located` to first-class" framing was broader
than needed — most types were already cross-checked; only inline-date and the value-below case remained.
- **Residual-of-the-residual (accepted, documented, ~never).** The flag-only detector DETECTS a
  value-below disagreement (caps conf + flags) but never SUBSTITUTES — so if the geometric re-OCR
  mis-seats and coincidentally reads the SAME wrong value as the rigid crop, they "agree" and it stays
  silent. Requires two independent reads to produce the identical wrong value → astronomically unlikely;
  named in `anchor.py`. No further slice planned. If ever pursued: it needs a fundamentally different
  signal (not another geometric read), and the real-doc A/B is structurally BLIND to this path (no
  value-below cross-supplier docs in the corpus) — unit tests are the only verification.

Working tree clean (all fixes committed; only the untracked handover + reports remain).
