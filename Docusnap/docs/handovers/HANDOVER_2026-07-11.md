### APPROVED FIX CYCLE (user said "yes, run it" — do NOT re-ask; run it first)

**Defect:** `computeSlipFixes` is count-blind and orientation-blind for symmetric confusion pairs
($↔S, 0↔O, 1↔I): "majority = truth" fails exactly when the majority is poisoned, which is the
scenario the tool exists for.

**Design directions to take into the cycle (gary + reggie design, Oracle LAST):**
1. **Alpha-prefix prior** — inside the leading letter-run of the dominant shape (e.g. `SO-`),
   prefer LETTER over DIGIT for symmetric pairs; digits belong in the numeric tail.
2. **Cross-scope corroboration** — the doc-type-wide (cross-supplier) per-position consensus must
   AGREE with the proposed target, else propose nothing (precision-first: silence over inversion).
3. **Confirm-time record** — the filed FILENAME preserves confirm-time truth (it's how the
   inversion was proven); a proposal contradicting the source docs' filename token is suppressed.
4. Never treat a "consensus" side as authority when its values/hints are themselves flagged.

**Smallest slice** = block wrong-ward proposals (the tool may propose nothing; it must never
propose toward a minority-vs-cross-scope form). **Tests:** pin the exact inversion scenario
(poisoned in-scope majority + correct minority → NO wrong-ward proposal); note `computeSlipFixes`
lives in the renderer — the cycle decides between extracting a pure testable module (the
anchorLabel mirror-twin pattern) vs an Electron-run renderer test. Existing backend guard:
`database/modules/test_field_value_history.js` (covers `renameFieldValue`, not the proposer).
