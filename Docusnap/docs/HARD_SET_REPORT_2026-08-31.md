# Hard Set — adversarial test corpus, first scored run (2026-08-31 night)

**Corpus:** `Desktop\Hard Set\` — 10 classes × 20 docs × 2 renditions (born-digital + scanned at
200 DPI with per-class skew/fade/blot), 400 PDFs + `ground_truth.json`, generated by
`stress_test/gen_hard_set.py` (7 synthetic issuers, buyer = Bramblewood Joinery Ltd, control docs
embedded in classes that need them). Scorer: `stress_test/score_hard_set.js` (app env mirrored,
DPI 200, 8 shards, the ONE `isAutoFileEligible` predicate for the would-file lane; RR_DB =
`db.backup()` copy of the live DB, mig 94, 2,335 confirmed docs).

**Arms:** digital cold · scan cold (empty-learning behaviour) · scan warm (the owner's real
learning loaded READ-ONLY — measures what a mature install does to brand-new issuers).

## Headline

**600 doc-arm scores, zero silent misfiles: `wrong + would-file = 0` on every class in every arm.**
Every wrong read was either flagged (validation note / sub-70 confidence) or EMPTY-held; every doc
held `below-floor` (the predicate's real verdict — new issuers are ungraduated, so nothing files).
The adversarial corpus could not make the app file a wrong document.

Controls scored clean in all three arms (credit_sign 0/3 bad, small_print 0/7 bad — after the
control rule was corrected to "silent-wrong or wrong type", since a held/flagged control is a
finding, not a broken harness).

## Findings by mechanism

1. **Boxed `meta_row` cells hold ref/date cold (the big FILL gap, not a safety gap).** Classes whose
   ref/date print as boxed label-above-value cells (multicol_money, table_total, logo_siblings,
   credit_sign, multipage, buyer_large) read ~0–15% cold and hold EMPTY; classes with plain
   `Label: value` lines (continental, small_print, edge_date) read 100%. The cold pipeline doesn't
   climb into bordered cells for the value under a label. Teach should heal it (a mapping zone reads
   the cell directly) — Chris's round tests that claim.
2. **Credit-note totals drop the sign in ALL four notations** — `(908.16)`, `908.16-`, `-908.16`,
   `908.16 CR` all read `908.16` positive (flagged every time, so contained, but the stored total on
   a manually-confirmed credit note would be sign-wrong). Same on `logo_siblings` sib_credit. 24%
   accuracy = only the plain controls score. Known family (`project_credit_note_type_family_20260807`)
   — now deterministically reproducible ×16.
3. **The buyer-issued steer goes SILENT on a warm install (top card).** Warm arm: all 7
   `buyer_issued_po` docs read supplier = `Bramblewood Joinery Ltd` with **no flag** (silent), where
   the cold arm flagged the identical wrong value. Bramblewood is a KNOWN supplier in the live DB
   (215 confirmed docs, 9 hints, 1 logo fingerprint) — learning legitimises the buyer-as-issuer
   steer and the identity-conflict flag disappears. Held at overall 31, so it cannot file, but Review
   presents the wrong issuer with no warning. This is the standing buyer-issued class (vet queue
   since 08-24) with a new, measured nuance: **maturity removes the flag**.
4. **A mature install refuses to invent an unknown issuer** — warm supplier ≈0% with EMPTY-held on
   almost every class where cold read the name fine (e.g. continental 90% cold → 0% warm). Fail-safe
   (nothing wrong committed), and it is the measured mechanism behind "first batch all-hold" friction
   on an established install: a brand-new issuer fills nothing until taught/confirmed once.
5. **Leading-digit date-in-ref again** — skewed/degraded docs put the DATE in the ref field
   (`ref: want 'INV-97969' got '04-07-2025'`, flagged). Same class as the realdoc baseline M=7. The
   corpus reproduces it on demand (degraded skew2/skew3, multipage carried_fwd, buyer_large
   ship_to_right).
6. **Thermal till-roll receipts land untyped** (overall 31, held; `got_type=null`). No Receipt type
   is installed on the live DB — the preset catalog HAS one, so this is an owner choice away from
   working; also a GT flaw (see below).
7. **Supplier fragment reads on scans** — `'Bay'`, `'Foods'`, `'Bay Foods'`, `'Lantem'` (rn→m),
   `'BILL TO'`, `'FROM GREYBURN…'` (fax header line wins) — all flagged/held, never filed. The
   two-word-lowercase-logo issuer (Lantern Bay Foods) is the weakest letterhead; fragment reads are
   the known garbled-issuer family.
8. **What the pipeline already does WELL under adversity:** EU/continental number formats (dot/space
   thousands, CHF, € after) 100% ref/date + 90% supplier cold; 9pt small print 100% (the light-text
   recovery + normal ladder); ISO/edge dates 65–100%; `balance b/f` vs the real total on statements
   100% total accuracy (never took the wrong row); same-logo sibling DOC-TYPE assignment 100% (type
   is never confused — only the boxed refs hold).

## Corpus/GT flaws found by the run (fix in gen before re-use)

- **thermal GT says `invoice` but the page prints RECEIPT** — with no Receipt type installed the doc
  goes untyped (held), so it scored as a type miss against a wrong GT. Either add Receipt to GT+gen
  or relabel the class.
- **Bramblewood as buyer overlaps the owner's real learning** — deliberate for the warm steer
  measurement, but it means the warm arm is NOT a pure "unknown issuers" bleed test. A future pure
  bleed run should use a fresh buyer name.
- The scorer's md mismatch lists truncate per class; use the `.jsonl` for full detail.

## Scorer traps pinned (for future harness authors)

- `isAutoFileEligible` refuses a **falsy doc id** as `'no-type'` (trust.js:983) — a synthetic doc
  must carry a truthy id or the whole would-file lane silently dies (first run did exactly that).
- TOTAL is scored only where the GT type defines a total-ish field (the 2026-07-29 rig lesson).
- EMPTY ≠ SILENT: a wrong field splits three ways — EMPTY-held (safe miss), flagged-wrong (caught),
  SILENT-wrong (the only dangerous kind). Conflating them buries the signal.
