## 1. Problem & goal

Arbitrary paperwork (statements, contracts, certificates, school letters) has no home in ScanFinder: a no-match doc carries `document_type_id NULL`, renders fallback invoice-shaped fields, blocks on a date it may not print, and files under the failure-scented `Unknown Company`. The feature is the "just file this, I'll find it later" promise: a **General Document** type that no-match docs fall back to, a one-glance review card confirmable with a single Ctrl+Enter, filing under `General/<year>/<month>`, and an **Auto-Title** (the doc's own biggest standalone heading) as the human-memorable handle and a `{title}` filename token. Retrieval is the already-live full-text search plus readable filenames; safety is that a generic doc is **review-bound by construction** — it can never auto-file.

## 2. User-facing spec (barry)

**Type:** "General Document", slug `general_document` — a place, not an apology ("Everything else" prints badly as a filename token; "General Document" files as `General-Document.…` and reads calmly in a type dropdown). **Exactly three fields**: Document Issuer (structural, blank allowed), Date (structural, scan-date default below), **Title** (`field_key='title'`, free text, editable, top of the stack). No reference (`ref_field_key: null` — first-class per `PRESET_CATALOG`; a forced ref trains junk-typing). No notes/keywords field — the doctrine line: *if the document prints it, it's a field; if you'd type it, it's a tag* — and tags are the later "My Stuff", not v1.

**Date policy:** keep Date REQUIRED; satisfy it with a **visible scan-date default** ("Scan date — click to change"). Date-less types kill retrieval (`Unknown Year/Month`); silent fallback violates "never a silent outcome"; a visible default is zero keystrokes, needs **no `ensureStructuralRoles` exemption**, and is human-gated by construction (it exists only at review time, after the import-time auto-file decision — fact B).

**Funnel moment:** when detection returns nothing, the doc opens **already typed General Document** with a provenance strip: *"ScanFinder didn't recognise this document, so it's set to file as a General Document — change the type if that's wrong."* The confirm cadence: glance (thumbnail, big Title, issuer+date, two-line snippet) → Ctrl+Enter. (Layer disagreement and resolution in §3.)

**Title UX:** the headline field row, ordinary editing (click, type — no modal). A wrong title costs a weak filename, never a wrong folder — that bounded blast radius is why editable-always + review-bound suffices with no confidence machinery. **Fail toward blank, never gibberish.**

**Filing:** blank-issuer General Documents file under **`General/`**, not `Unknown Company` (there it IS a failure signal; here blank is designed — typed docs keep `Unknown Company`). Default filename gains `{title}` (§6, disagreement noted).

**v1 cut list:** tags/My Stuff · Teach-Me Funnel (needs v1's usage data) · per-type filing patterns · glance-card redesign · Search UX changes · home preset pack.

**Success metric:** the **one-keystroke rate** — share of General Documents confirmed with zero field edits (no corrections rows); target >50% in early use, instrumentable from existing data. Guard rails: corpus decision-identical ON, M=0/M_type=0; zero `Unknown Company`/`Unknown Year` folders from generic docs. Owner's kitchen-table test: 20 mixed real documents filed at glance speed, any one re-found next day in under ten seconds.

## 3. Fallback mechanism (gary)

**Where None→generic happens: Electron-side, at the insert seam** (`processing/handler.js:2307-2314`): when `msg.document_type` is null AND the generic type exists+enabled AND the switch is on → `document_type_id = getGenericType(db).id` (new pure-ish helper in `document_types.js`: SELECT by slug + `enabled=1`). The Python pipeline stays byte-identical — extraction ran type-less exactly as today (no slug arming format/qualification gates, no anchor/template scope change). Pre-extraction assignment (option a) is the wrong layer — blast radius across the staged pipeline for zero gain. The seam relies upstream on `detect_document_type` None being definitive AFTER the banner heading re-read (`process_docs.py:532-544` runs before the emit, so a garbled red "WORKSHEET" resolves its true type before fallback can claim it).

**Oracle C1 — the SECOND insert seam (reprocess), missed by all four specialists:** `applyReprocessResult` (`handler.js:1101-1160`) resolves `result.document_type` name→id itself and never consults the fallback — without a change, a pre-existing NULL doc reprocessed after enabling STAYS NULL. **Resolution adopted:** add the same mapping there, gated `priorTypeId == null && result.document_type == null && switch-on`. The gate direction is load-bearing: a TYPED doc whose reprocess detection returns None must NEVER be dragged to generic (at `handler.js:1140` a type flip requires `priorTypeId != null`; the new branch must not bypass that). Tests cover BOTH directions (NULL doc reprocessed → mapped; typed doc with None reprocess detection → type unchanged). This also makes §11 Q6's backlog answer natural: reprocess IS the re-check path.

**Auto-file posture — the non-negotiable pair:** the mapping DELETES the `'no-type'` refusal (`trust.js:422-423`) for these docs, and `_maybeAutoFile` runs on every import (`handler.js:2424`) with confidence computed independently of the type mapping — so the mapping and an explicit replacement refusal ship in the **SAME commit**: in `isAutoFileEligible`, immediately after the dtRow lookup (~`trust.js:429`), `if (slug === GENERIC_SLUG) return { eligible:false, reason:'generic-type' }`. One shared predicate covers both auto-file sites. **PINNED INVARIANT: a generic doc never auto-files**, at any confidence, any slider, any graduation.

**Oracle C4 (premise correction folded in):** at overall confidence 100 the auto-file gate is **GATE-FREE by default** (`trust.js:480-484` — the strict at-100 gate is opt-in via `strict_100_autofile`), so this refusal is the ENTIRE wall between a 100-conf generic doc and `_maybeAutoFile`. PIN 2's battery must assert the refusal at conf 100 with `strict_100_autofile` OFF (the shipped default), at slider 80 AND 100, on a graduated scope — and the refusal must sit BEFORE the floor logic (the proposed ~`trust.js:429` placement is correct).

## 4. Date policy mechanics (gary + eric)

**No roles exemption.** `ensureStructuralRoles` (`document_types.js:446-454`) forces the date role — the generic type WANTS it (year/month folders). `validateConfirm` (`renderer.js:2498-2528`) keeps its hard block; the softening is a value, not a weakened guard. (Eric verified an UNSET role is already skipped at `renderer.js:2458-2466` — recorded so nobody builds an unnecessary renderer exemption.)

**Prefill vs one-click (disagreement) — resolution: prefill (barry + gary, 2-of-3), with eric's wiring.** On `renderFields` for a generic-slug doc with an empty date input: prefill DD-MM-YYYY from `doc.processed_at` (already in the payload — `documents.js:48-49`, `SELECT *`), paint a `.field-note` "Scan date — edit if the document shows its own date", and record `corrections[dateKey] = {original_value, corrected_value}` exactly per the established in-renderer correction pattern (`_clearSuspectReadsForNewIssuer`, `renderer.js:1948-1951`) so the value persists through confirm. Zero keystrokes is the point of the feature; eric's one-click button in `#confirm-config-note` survives as the fallback affordance if the user clears the prefill and hits the block. Deliberately **NOT an import-time extraction row** — a machine-written date row muddies confidence semantics and creates a value auto-file could someday trust; renderer-only, go-forward-only, no back-fill.

**Write path:** the prefill flows confirm → corrections → the central `normaliseDate` (`reviewService.js:83-90`) — format drift harmless, zero new IPC. **Folder derivation needs nothing special**: the confirmed date value drives `{year}/{month}` normally. Cosmetic note: `processed_at` is UTC `CURRENT_TIMESTAMP` — format the LOCAL date (an overnight off-by-one is visible and editable).

## 5. Auto-Title design (reggie's rules, gary's seam)

**Where it runs:** new pure module `python_backend/extraction/title_pick.py` — `pick_title(page1_text, supplier_name, caption_vocab) -> {title, line_index, score} | None`. Deterministic, no I/O, no env reads inside. NOT an extension of `detect_document_type` (byte-identical-gated, phrase-driven; titles need a different signal). **Seam:** `process_docs.py`, AFTER `engine.extract` + `sanitise_extractions`, gated on `document_type is None` + `AUTO_TITLE` — the same condition the Electron fallback maps on, so title rows are written precisely for the docs that become generic. Post-engine injection means `overall_confidence` is already computed → zero pipeline interaction; the row rides the existing `msg.extractions` insert loop (`handler.js:2339-2346`).

**Storage:** an extractions row `field_key='title'` — zero plumbing into search, filing `allValues`, XML; **Review rendering additionally requires the generic type to SHIP a `title` field def** (eric's correction of fact C: `renderFields` iterates the type's field defs, `renderer.js:1884-1891`). No migration, no `documents.title` column. **Method/confidence:** `method='auto_title'`, **confidence 60** (gary 60 vs reggie ~70 — resolved to 60: ≤69 keeps it below the review threshold by construction, and the generic-type refusal makes it moot anyway). **Scope v1: generic/no-match docs ONLY** (pinned) — typed docs' biggest heading is usually the type itself, and a typed-doc title row would risk corpus churn and collide with a custom type that owns a `title` field key (reggie's named collision seam — avoided outright by the scope gate).

**Oracle C2 — seeding exclusion (missed by all four):** on reprocess the doc carries `--known-doc-slug general_document`, arming `keyword.seed_field_labels`' free-text party branch for the generic field set — and the title field's label is **"Title"**, a genuinely printed caption ("Title: Mr/Mrs"). A seeded `title='Mr'@75 keyword` read would then REPLACE the carried `auto_title` row via `mergeReprocessRows` 'used_new' (`handler.js:136-150` — new wins when both have values): a silent title downgrade. **Exclude field_key `title` from the seeding branch** (one-line key exclusion). Unit: a generic-typed doc printing "Title: Mr" keeps its auto_title/empty title.

**Oracle C3 — hints exclusion:** a confirmed title feeds `supplier_hints`, and the FIRST stale title could hint-fill an empty title on a same-supplier reprocess (the variability guard only disarms at ≥2 distinct values). A title is per-document by nature: **exclude `title` from `_apply_hints`**.

**Oracle C5 — reprocess title lifecycle (pinned):** `pick_title` does not re-run on reprocess (type ≠ None there), so the title row survives via the absent-field carry (`handler.js:152-171`); a machine-authority flip generic→real correctly DROPS it as `dropped_stale_type` with the flip note — **assert the drop as INTENDED** so nobody "fixes" it. C2/C5 tests must exercise the REAL reprocess invocation (`applyReprocessResult` + `mergeReprocessRows`), not pure helpers — the merge is exactly where the title dies quietly.

**Selection rules (reggie, condensed — full brief is the build spec):**
- *Candidates:* page-1 lines, column-split via the imported `_COL_BREAK_RE` (`keyword.py:325` — never hardcode 4 spaces). Trailing-code strip first (mirrors `keyword.py:345-353`) so "Certificate No. 10023" reduces to its word core. Gates: 3–60 chars post-strip (60 = the `sanitiseValue` cap), 1–7 words, ≥3 alpha, alpha ratio ≥0.7, digits ≤0.3. Rejection regexes per FP class: page markers, date lines, contact/chrome/URL/phone, UK postcode (twin `validation_patterns.postcode_uk`), street lines, salutations/prose (ends `[.;,]`), colon-captions, structural markers (`Section B`), known captions via `value_is_caption` (the shared G3b vocab), forbidden pure-generic singles ({invoice, statement, copy, urgent, draft, …}), and company-name guards: legal-suffix reject (ltd/plc/llp/…), supplier token-overlap ≥0.6 (via `text_normalise`), address-block adjacency (next 2 lines match street/postcode/contact → inside an address block).
- *Scoring:* `w_pos = max(0, 2.0 − 3.0·(i/total))` + standalone-line 1.0 (segment-only 0.25) + case (ALL-CAPS 0.75 / Title Case 0.5) + 2–5-words 0.5 + TITLE_NOUN 1.0 (frozen provisional set: certificate, agreement, contract, statement, policy, notice, report, warranty, licence, …). Winner = max score, tie → topmost.
- *Acceptance bar:* score ≥3.0 AND (contains a TITLE_NOUN, or is ALL-CAPS standalone in the top 10 lines *and not line 1* — the letterhead guard for unresolved suppliers). Nothing clears → **None. Empty beats junk — pinned.**
- *Validation ladder:* trigram garble via `wordness.token_logprob` **called directly** (thresholds −3.3 weak / −4.2 hard floor) — this bypasses the `_CHROME` stoplist by construction (it lives only inside `name_structure_flag`), so "Statement"/"Certificate" are legal titles with **zero edits to wordness.py**; `ref_bleed` reject; re-assert digit/length; display case = as printed, except ALL-CAPS → Title Case with ≤3-char caps preserved ("EPC Certificate").

No `validation_patterns` entry and no renderer `RegExp` twin — free text; state this in the module docstring so nobody adds one one-sided. Embeddable-python rule: import `from extraction.title_pick import pick_title` — never bare; verify with `python -P` against `vendor/python` (the 5d5fd8c lesson).

## 10. Risks & named seams (merged, deduped)

1. **The refusal seam is the whole safety story** — mapping without the trust guard gives no-match docs an auto-file path they never had. Mitigation: same-commit pairing + PIN 2.
2. **Rushed one-keystroke confirm of a detection-failure doc** (a mangled invoice files under General with a scan date). Accepted Barry trade-off; mitigation: review-bound construction, provenance strip, type dropdown in view. The near-miss guard is the owner refinement (§11).
3. **`document_type_id NULL` no longer ambiently means "undetected"** — search/type filters count generic docs (cosmetic); Review renders generic fields instead of `FALLBACK_FIELD_KEYS` (intended).
4. **Generic confirms entering the template ecosystem** — disabled for `GENERIC_SLUG`; pinned trade-off: no template learning on the pile in v1.
5. **Switch interplay:** `AUTO_TITLE` on with `GENERIC_FALLBACK` off writes title rows for docs that stay NULL — invisible in Review (no field def), harmless-beneficial in search. Mitigation: Settings presents auto-title as a sub-toggle of the fallback toggle.
6. **Title-row leakage:** if the operator retypes a generic doc as Invoice, the title row silently stops rendering, never enters `allValues`, cannot reach a typed filename (verified — `allValues` is built from on-screen inputs).
7. **`{title}` in the default pattern** (the one live disagreement): barry wants it (the retrieval story — otherwise `General/` is a wall of `General-Document.15-03-2026.pdf` + `-DUPLICATE` chains); eric/gary ship registration-only. **Recommended resolution: ship it as slice 6, last, own gate** — byte-identical typed filenames are mechanically provable (title only exists on generic docs in v1 + empty-token collapse), and the pinned seam is that any future typed-doc title extension MUST revisit this default before shipping.
8. **User-created type already slugged `general_document`** — adopted as THE generic type; acceptable (it is their generic type), still review-bound by the slug-keyed refusal; documented.
9. **Renderer prefill untestable in the JS battery** — covered by the manual gate + existing reviewService normaliseDate tests.
10. **Letterhead-as-title residual** (noun-carrying straplines, "Annual Statement" mastheads) — position decay + line-1 rule + supplier dedupe cover most; residue is one-click editable and never files silently.
