## Mechanism
- **Join the WORKING COPIES**, not the raw folder segments: auto-rotate bakes rotation into `/Rotate` on the working
  copy, and `pypdf writer.add_page` clones `/Rotate`, so per-page rotation is preserved for free (the folder segments
  are un-rotated + drained to `Processed/`). New primitive `python_backend/pdf_join.py` (BSD-3 pypdf; repeatable
  `--file`, atomic `--out`; pinned by `test_pdf_join.py` incl. the rotation proof).
- **Reconstruction from drift-proof signals only** (no persisted manifest exists): the splitter filename contract
  (`split_plan.SEGMENT_PAGE_RE`/`segmentPageRange` — imported, never re-derived, C6), the doc's own pair note
  (`pairPartnerPage`), the SAME import folder, a **reciprocal** note match (the candidate names us back), and a
  contiguous page span. Refuse on 0 or >1 candidates so a duplicate-`<stem>` collision across two scans never
  cross-binds (C2). `wantPartnerPage` (the button the user saw) picks the exact pair on a middle page of a chain.
- **Order (C1, load-bearing):** in ONE txn — clear BOTH pair sentences, stamp the mig-176 "look first" note on the
  survivor, set its `page_count`, soft-delete the partner. The mig-176 stamp lands BEFORE the renderer's reprocess so
  `carrySegmentHold` re-attaches THAT note (a real held checkpoint), never the stale pair sentence. (`reprocess` does
  NOT clear the pair sentence — it re-attaches notes; the earlier "reprocess clears it" premise was false.)
- **Atomicity / rollback (C3):** join → backup the survivor's working copy to `.c12bak` → atomic swap → txn → delete
  the backup. On any post-swap failure the backup is restored; the DB txn is all-or-nothing; the original in
  `.sf_separated_originals` is never touched (the ultimate anchor). The result lands `needs_review`, held by the
  mig-176 note, and NEVER auto-files.
- **Gates (C4):** `requireRole('admin','edit')`; `canAccessDocument` on BOTH the survivor and the partner
  (existence-hiding — the 2026-09-18 audit-debt lesson); the workflow edit-lock on both; refuse if either is
  `confirmed`/`deleted`/working-copy-missing. A filed doc is never a join target (a confirmed partner is not even a
  candidate — the `needs_review` filter).
- **UI (C5):** one "Join with page N" button on the pair reason panel (the raw folder path dropped from the copy);
  a confirm that previews BOTH pages (thumbnails) so the user sees what merges; on success, navigate to the survivor
  and re-read it. Undo = "Split again" (the retained original + the soft-deleted partner in the bin); no new ledger.
