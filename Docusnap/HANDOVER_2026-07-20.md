## Root causes worth remembering (proven, not theorised)

- **Fresh-install type hole (`04a6af1`).** Owner's own log + DB timestamps proved it:
  `09:23:32` PO template created → `09:26:46` dockets imported → **`09:28:19` Delivery Note type
  created**. The engine detected "Delivery Note (93%)" from the SHIPPED keyword buckets, but that
  name mapped to no INSTALLED type (Delivery Note is a PRESET, not a built-in), so
  `detected_name_slug = None` — and **both** type-refuse guards (logo path AND keyword path) are
  conditioned on a truthy `detected_slug`, so they silently DISARMED and a same-supplier PO template
  stamped its slug. Protection was strongest for a configured install and ABSENT for a new one.
  FIX: derive the slug the type WOULD have (`_slug_from_type_name`, char-for-char parity with JS
  `safeSlug`, verified on 10 inputs). Kill `DETECTED_SLUG_FALLBACK=0`.
  **The same log proves the guard works when the type exists** — every Marlowe INVOICE in that run
  correctly refused the identical PO template.
- **`confirmed_count` 0× (`277a107`).** Only ever bumped by `templates.update()`, which runs on the
  taught-confirm branch — an ordinary confirm never touches it (owner's DB: 0/1/0 vs 20/20/19).
  NOT cosmetic: it feeds the sibling tiebreaks at `template_matcher.py:179` and `engine.py:696` plus
  the ORDER templates reach the matcher — all inert at 0. `getAll` now serves the LIVE count.
  `liveConfirmedCounts` returns **null** (not an empty Map) when uncountable, so a fixture without a
  `documents` table keeps the stored column instead of zeroing every template.
  Kill `TEMPLATE_LIVE_COUNTS=0`. **A pin asserting "getAll is UNTOUCHED" was deliberately flipped.**
