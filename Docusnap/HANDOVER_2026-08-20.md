## ⭐ THE FINDING OF THIS SESSION — the app's own auto-filing blinds its corroboration arms

Measured on the round-9 DB while checking Oracle's expectation that the engine arm was already
licensed there. It is not, and the reason matters far more than this arc:

| Pelican `invoice_number` | count |
|---|---|
| confirmed `PI/` values in the database | **27** |
| ...that the learned-format corpus actually COUNTS | **4** |
| human confirms | 4 |
| `auto_threshold` confirms | 14 |
| `scope_sweep` confirms | 9 |

`learning_exclude_machine_confirms` (ON) removes every machine confirm from the substrate
`getFieldFormats` counts. **Whole install: 38 human vs 331 machine — 89.7% of the confirmed corpus
is invisible to every dominance and format reader.**

The dominance bars that license the P adopt lane, the dominant-value snap and the prefix guard
(`≥5 extractable prefixes, ≥5 dominant, ≥0.90 share`) therefore **cannot arm on a scope the app
files well**. Pelican sits at 4 — short by one. So the arm designed to fix the Pelican class stands
itself down precisely because the app got good at filing Pelicans. **The better the auto-filing
works, the blinder the reading gets.**

**DO NOT just flip the switch.** The exclusion exists for a real reason (a machine echo voting for
itself is the B7 loop), but an `auto_threshold` confirm passed the full trust gate, which is not the
same thing as an echo — and *that distinction* is the design question. Task #13; needs gary + Oracle.

**Correction to an earlier claim of mine:** the "27 confirmed PI, comfortably licensed" figure in the
2026-08-19 handover was measured against the raw `extractions` table, not against the counted
substrate. Oracle repeated it in good faith from that note. The counted number is 4.

only one of the two that works**, because it needs no dominance at all: a human licensed it.

## SHIPPED (both DEFAULT OFF)

### `ab967df` — Design 1: the P adopt lane reads two more note classes (`REF_PREFIX_CONFUSABLE_ADOPT`)
Of six sampled round-9 misreads only THREE were the rawwitness class the lane inspected. The others
carried `template_mapper`'s wider-reading note or Gate C's "doesn't appear on this page as written".
Licensing is untouched — same bars, same both-forms refusal, same shape check, same
fail-toward-Review. Note MARKs are hoisted and composed into the notes at their WRITE sites, so a
reword makes the matcher inert rather than mis-matching.
**W3, the new witness:** the adopted string is PRINTED on the page. The candidate still comes from
history; W3 only asks whether that string is there — so Gate C's premise is satisfied, not bypassed,
and the clip class it exists for (`VXS986` vs printed `VXS98624`) stays refused.
**W3 is leg 1 of page-match v2 ONLY (Oracle C5), extracted pure (no trace, no log).** Leg 2 is a
backed-confusable tolerance; as a witness for a candidate that is itself a one-glyph variant it
would let the misread witness its own correction. Pinned.

### Design 2: the human-licensed class correction (`ref_class_fix_enabled`, migration 74)
`src/services/refClassFix.js` (pure predicates) + `src/services/classFixService.js` (every write),
hooked LAST in `reviewService.confirm`. Correct one reference by a single confusable glyph inside its
code prefix; the same byte-exact substitution reaches the sender's other QUEUED documents; a bar
reports it afterwards with **Show what changed** and **Undo**. Nothing is filed.
**The narrow rule (both designers, independently):** correcting a `P1` does NOT license rewriting a
`PL`. Two corrections instead of twelve, each explicitly licensed.

**Oracle's 8 conditions, and the three that were premise errors:**
- **C1** `corrected_to` is NEVER written on a sibling. It looks like the obvious badge and is a trap:
  `trust.js` counts a non-empty `corrected_to` as `flagged` unless a **user-visible** toggle is on,
  and the Review flag summary counts it with no carve-out at all — twelve just-fixed documents would
  each say "1 field was flagged", and one setting change would hold them shut forever. The **method
  marker** carries the badge: durable, gate-free, and already needed by three other mechanisms.
- **C2** class-fixed rows are excluded from the learning corpus, **with** an `OR a correction exists`
  carve-out — `updateExtractionValue` never rewrites `extraction_method`, so without it a row the
  human later fixes stays excluded for the life of the install.
- **C3** *reggie's catch, the one that would have bitten:* `mergeReprocessRows` takes the fresh row
  wholesale, so **a Reprocess All silently reverted every propagated value** — and the marker going
  with it, the undo then refused too. Guarded at `handler.js:975`, the line that actually does it.
- **C4** Tier 2: the value travels; the blocking note lifts only on that document's own witness and
  only for the four enumerated note classes that name the old value. Everything else is REPLACED
  with a note that still holds.
- **C6** the one-time ask, remembered per class — fires only where the sender's history holds BOTH
  forms (the owner's mature install, where three confirmed `P1` rows are almost certainly
  mis-confirms). Asking every time is what the owner banned; asking once is what he offered.
- **C7** own service, invoked last, own `!_via` + `!bulk`, own transaction, sweep-mirroring filters,
  one cap, `document_id <> source` on every statement. **C8** a `class_fix_applied` audit row.

**Also corrected Oracle's premise (a):** the both-forms refusal was not one predicate over one
evidence set — the engine reads `_cmp_norm`-collapsed keys, JS reads raw ones. Now ONE predicate
(`ocr_corrector.both_forms_established` + its JS twin), each normalising inside itself, pinned by
`python_backend/tests/both_forms_corpus.json` whose two load-bearing rows are a **mixed-case head**
and a **separator variant** — without those two a real divergence greens.
