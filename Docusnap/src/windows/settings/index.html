Import & processing

These apply to every import — manual, watch-folder and background alike.

Auto-file 100%-confidence documents
Skip Review for documents read with full confidence — file them automatically after processing
Auto-file confidence threshold
File automatically when overall confidence is at least this — and the document is fully typed with no field flagged for review. Lower it once you trust the reads on your regular suppliers (confidence climbs toward ~98% as Scan Finder learns them). Applies only while auto-file above is on.
100%
Read values that wrap onto the next line
When a field is taught to wrap (e.g. an address whose first line ends “-”), read the line below and join them. Single-line values are unaffected.
Auto-rotate sideways or upside-down scans
Detects a page scanned in the wrong orientation and turns it upright — both for reading and in the filed PDF. Only acts on a confident result; pages it isn't sure about are left as-is.
Recover long reference numbers cut off by the crop
When a taught reference is longer than the example it was taught on, the reader can clip the last character (e.g. “PO-58987” read as “PO-5898”). Turn this on to extend the read to the full value. Off by default.
Trim the label off the start of a read value
On slightly shifted scans the reader can pick up the label text just before a value (e.g. “PO-27425” read as “PO9974A9C”). Turn this on to clamp the read to just the value. Off by default.
Recover a reference whose prefix was misread
When a reference's letter prefix is garbled to a symbol (e.g. “PO-17039” read as “0-17039”) but another read on the page has it right, use the correct one automatically — only for a sender whose references all share that prefix. Off by default.
Correct a reference that lost a cross-check
When ScanFinder re-checks a taught reference against a fresh read of the whole page and the two disagree, it can occasionally trust a mis-read of the page over the correct value. When the correct value is backed by the document's other reads and is present on the page, ScanFinder keeps it instead of the mis-read. Off by default.
Double-check references and dates against the whole document
After reading, ScanFinder compares each reference and date against every other read it made of the same field. If the chosen value can't be found anywhere else but a different value is backed by several independent reads and printed on the page, ScanFinder uses the backed value instead. Off by default.
Tidy stray marks from taught reference reads
When a taught box accidentally catches a stray dot or mark from the label next to it (e.g. “. DN-60902”), and a second independent read of the same spot shows the clean value, ScanFinder files the clean value. The two reads must agree exactly. Off by default.
Snap taught boxes to the printed text
When a taught reading spot lands slightly off on a tilted or shifted scan, ScanFinder adjusts the box to cover the full printed value it overlaps — never grabbing neighbouring text — so references and dates aren't cut short. Off by default.
Remove label fragments from taught reads
When a taught box catches the tail of its own label (e.g. the “o.” of “No.” read as “o. DN-67428”), and an independent read of the same spot shows the value without it, ScanFinder files the clean value. ON by default — you can turn it off here.
Complete a cut-short taught read
When a taught box cuts a reference short (e.g. “DN-6742” for “DN-67428”) and two further reads of the same spot agree on the full value in the sender's usual format, ScanFinder files the full value instead of asking you to verify. ON by default — you can turn it off here.
Grow a taught box that cuts through the printed value
When a taught reading spot's edge lands mid-word on a document (a longer reference than the one it was taught on, or a shifted scan), ScanFinder widens just that read to the full word and files it only when an independent check of the same spot agrees — otherwise the shortened reading is sent for review instead of filing silently. ON by default — you can turn it off here.
Catch cut-short dates
A date read with its year cut off (e.g. “07-01-20-” from “07-01-2026”) is no longer accepted as-is — ScanFinder retries the read or sends the document for review, so a shortened date can't be filed as the wrong year. ON by default — you can turn it off here.
Stricter matching for number-like reading spots
A taught reading spot identified by a number (rather than a printed label) must match that number exactly — so a different date or reference nearby can never be mistaken for it. ON by default — you can turn it off here.
Align taught reading spots on straightened pages
When a document was taught on a straightened page, ScanFinder aligns every taught reading spot to the straightened view of each new document — so a slightly tilted scan reads the same values the teaching showed. The first re-read of a sender measures the teaching page's tilt; reads after that use it automatically. Off by default.
Re-read a taught spot off its label when the box clips the value
When a taught reading spot lands a hair off on a new document and cuts through the value, ScanFinder re-reads it from where the printed label actually sits — so the right value is shown (flagged for a quick check) instead of a garbled one. Works best with word-snapping on. ON by default — you can turn it off here.
Don't flag a taught value when only its last character was misread
When a taught reading spot clips the last character of a code but the label-anchored re-read (confirmed by a second reading and matching this sender's usual format) recovers the full value, ScanFinder files it without a needless "check this" flag. Only applies when the fuller read is clearly more confident. ON by default — you can turn it off here.
Never file an impossible date over a valid one
If a taught date reading spot misreads a date into something impossible (e.g. day 33), ScanFinder keeps the clearly-read date from elsewhere on the page instead — flagged for a quick check. Only when the other read is confident and a genuine calendar date. ON by default — you can turn it off here.
Never file a wildly-future date over a valid one
If a taught date reading spot misreads the year into the far future (e.g. 2096 instead of 2026), ScanFinder keeps the clearly-read date from elsewhere on the page instead — flagged for a quick check. Only for dates more than ~3 years out, so a genuine post-dated document is never affected. ON by default — you can turn it off here.
Double-check a taught date when the box clips a digit
When a taught date-reading spot is drawn tightly and clips the first digit on a slightly-tilted scan (e.g. “03/04/2026” read as “01/04/2026”), ScanFinder takes a second, wider reading of the same spot; if it clearly disagrees, the date is flagged for a quick check instead of being filed silently. Never changes a value on its own. ON by default — you can turn it off here.
Recognise a document's type from a large title heading
When a document's big title (e.g. “CREDIT NOTE”) is printed large or widely letter-spaced, the reader can drop it or split it, and the document is mis-typed (a credit note read as an invoice). ScanFinder takes a quick second look at the title and corrects the type — on both new imports and reprocessing. ON by default — you can turn it off here.
Check a credit note's total for a missing minus sign
A credit note's total is money going back to you, but the minus sign in front of it can be lost when the page is read — so a £160.32 credit is filed as a £160.32 charge. ScanFinder checks the total's sign against the document's type and flags it for a quick check instead of filing it silently. It never changes the amount itself — you type the minus. ON by default — you can turn it off here.
Trust a template's saved sender name over a misread letterhead
When you save a template you tell ScanFinder who the sender is. If the letterhead on a later scan reads badly — a stray mark turning “Castellan Security Systems” into “tastellan Security Systems”, or into a scrap like “an:” — that misreading can currently replace the name you saved, filing the document under the wrong sender. This keeps your saved name when the reading is clearly the same name misread, or is too short to be a company name at all. A genuinely different company still wins, so re-teaching a template still works. Off by default.
Take a wider second look when a taught box clips a reference code
When a taught reading spot is drawn slightly too tight for its code, the first characters can be cut off (“PO-48009” read as “-48009”). ScanFinder re-reads the same spot a little wider and either recovers the full code or flags the disagreement for a quick check. Off by default.
Don't mistake a VAT registration number for a VAT amount
Most letterheads print a VAT registration number (“VAT Reg GB 651 0027 84”). ScanFinder could read those digits as the VAT amount, which then made the totals look like they didn't add up — so documents that were perfectly correct came to you saying “please check”, with nothing wrong to find. This tells the two apart and reads the real VAT line further down instead. It also flags a total that looks like a part-total, so a net figure filed as the grand total is still caught. Off by default.
Read a taught value that sits under its heading, not the heading itself
When you teach ScanFinder where a value is, it also notes the wording beside it so it can find that value again on the next document. If you drew the value underneath its heading — common on delivery notes, where “Delivery Note No.” is on one line and the number on the next — ScanFinder could treat anything within a few lines as being “on the same line”, and file the heading word itself (“Delivery”) as the reference number. This measures the two boxes properly, so a value you taught below its heading is read from where you actually drew it. Where it then can't read the value confidently the document comes to you instead of guessing. ON by default — you can turn it off here.
Never accept a heading word as a reference number
A reference number — an invoice number, credit note number, delivery number — is always a code with digits in it, never a plain word. ScanFinder already refused word-only readings for order numbers; this applies the same rule to every reference field, including the ones on document types you create yourself, so a heading like “Despatch” or the sender's own name can't be filed as the document's reference. When a word is refused ScanFinder usually reads on and finds the real code beside it. ON by default — you can turn it off here.
Keep a taught field reading from the spot you pointed at
When you point out a field, ScanFinder remembers where its value sits relative to its heading. On a document with two blocks side by side — “Customer” on the left and “Ship To” on the right, printed level with each other — it could pick up the neighbouring block's heading instead of your value and file that as the customer's name. This checks that anything it reads along the heading's line is where you taught the value to be; if it isn't, it goes back and reads the spot you actually pointed at. ON by default — you can turn it off here.
Read the total from the row you pointed at, not the one above it
A totals block moves up and down the page depending on how many lines the document has, so the box you drew around the total on one invoice can land a row too high on the next — usually on the VAT line. The amount it finds there looks perfectly valid, so nothing further down catches it, and the wrong figure is filed. On the test set this was 19 of 23 wrong totals, each one exactly the true total divided by six — the signature of reading a 20% VAT row. This measures a one-row shift properly and re-reads from where you actually pointed. It only acts when the heading it found is the exact wording you taught, so a similar heading nearby can't redirect it. ON by default — you can turn it off here.
Read a whole amount when it's longer than the one you taught
Amounts are printed right-aligned, so a bigger figure grows to the left — past the edge of the box you drew. If you taught the total on a £99 invoice, a £10,603.44 total on the next one can be read as “0,603.44”. This lets the box stretch left to take in the whole amount. It will only do so when it can show nothing was lost: if stretching would drop the leading digits instead of recovering them, it keeps the original reading and the document comes to you. Works alongside the two reading-accuracy switches above it and does nothing on its own. ON by default — you can turn it off here.
Allow for a slightly crooked scan when reading a taught field
When you point out where a field sits, Scan Finder records that position against the page you taught it on. The next scan of the same document usually goes through the scanner at a very slightly different angle, so the remembered box arrives tilted against the printing — often by around half a line, which is enough to read the heading above a value, or the address line below a company name, instead of the value itself. This tilts the remembered box to match each page as it arrives. It does not straighten or alter your document in any way; it only measures the angle and reads in the right place. ON by default — you can turn it off here.
Keep the sender's name you confirmed when the letterhead reads as nonsense
Once you've confirmed who a document is from, Scan Finder keeps that company name against the layout. On a poor scan the letterhead can come back garbled, or the reading can pick up something that isn't a company name at all — a date line, a VAT number, a page heading. On the test set that happened on 42 documents out of 135. Scan Finder already spots this and tells you (“Letterhead may read ‘Castellan Security Systems’ — detected ‘DATE 14-03-2026 Job Ref JB-8887’”); this lets it act on what it has already worked out, and keep the name you confirmed. A genuinely different company still comes through, and re-teaching still replaces a name that has gone out of date. ON by default — you can turn it off here.
Trust a taught box when the field has no printed label to check it against
When you point out where a field sits, Scan Finder also notes the printed wording beside it (“Invoice No”, “Balance Due”) and uses it to check the page hasn't shifted before it reads. The company name at the top of a letterhead has no such wording — there is nothing to look for. Until now Scan Finder treated “no wording to check” the same as “checked and failed”, and fell back on a whole-page estimate of how the scan had moved; on a scan that estimate can pull the reading onto the wrong line, so what got saved as the sender was a page heading, a street address or a VAT line instead. With this on, it only falls back that way when there really was wording to find and it could not be found. On the test set the sender's name was wrong on 22 documents out of 140 for exactly this reason, and all 22 read correctly with this on. ON by default — you can turn it off here.
Check the sender's name is really printed where you drew the box
Works alongside the setting above. Once you have confirmed who a document is from, Scan Finder keeps that name against the layout. When a scan arrives shifted or crooked, the box you drew around the company name can land on the wrong part of the page and read something else — and that reading replaces the name you confirmed. This looks in the area around where you drew the box (half as much again in each direction) and checks whether the confirmed name is actually printed there. If it is, the name you confirmed is kept. If it isn't there, or that part of the page could not be read at all, nothing changes. It can only keep a name you already confirmed — it never invents one, never raises how sure Scan Finder is, and a document genuinely from a different company still comes through. ON by default — you can turn it off here.
Treat a matching read of the sender's name as confirmation, not a correction
When the box you drew reads back exactly the company name you already confirmed, Scan Finder currently replaces the confirmed name with that reading — the same words, but held with less certainty. On the test set that dropped four documents below the level at which Scan Finder is willing to file them without asking you, for reading the right answer. With this on, the name you confirmed simply stands. A document genuinely from a different company still comes through, and re-teaching still replaces a name that has gone out of date. Off by default.
Don’t let a field’s own printed wording be saved as its value
When you point out where a reference or account number sits, a shifted scan can make that box land on the printed wording beside it instead — so Scan Finder saves the word “Ref”, “Account” or “Delivery” as the reference number. A reference is a code, and a code always carries at least one number, so a value with no numbers in it at all is refused and the document comes to you instead. ON by default — you can turn it off here.
Stop one printed code filling three different fields
Fields that hold a reference of some kind all start out looking for the same general wording (“Ref”, “No.”, “Number”), so a single code printed on the page can be picked up as the invoice number AND the order number AND the account number at once. With this on, when one field matches that code by its own specific wording, the fields that matched only general wording give it up. It can only ever remove a duplicate — it never moves a value to a different field. ON by default — you can turn it off here.
Trust the document’s own printed heading when deciding what it is
Scan Finder works out what a document is by adding up evidence, so a built-in type that recognises a lot of wording can outvote a type you created yourself that recognises only its own name. When that happens, a template you taught is filed under a type its own future documents can never be recognised as — on one test run 35 documents matched no template at all, and nothing on screen said why. With this on, if exactly one of your document types has its own name printed as the heading at the top of the page, that type wins. ON by default — you can turn it off here.
Query a reference or date that doesn’t look real before filing it
Two checks that only ever ADD a note — they never change a value or choose a different one, and a document carrying a note is never filed without you seeing it. First: a reference whose shape is scanning noise rather than a code (jumbled capitals with no run of digits). Second: a date whose year is printed nowhere on the page, which is exactly what a misread digit produces. Genuine codes like “HTS-SO-12013” or “PD/25/1197” are left alone. ON by default — you can turn it off here.
Read the sender’s name off the letterhead the first time you see a company
The first document from a new company has nothing for Scan Finder to recognise — no logo it has seen before, no name you have confirmed, no layout it has been taught — so the sender is left blank even though the company name is printed across the top of the page. With this on, Scan Finder reads the largest name at the top of the page (ignoring the recipient block and the document heading) and offers it: the name appears with a “Use this” button and a note asking you to check it is the sender and not the customer. It never fills the name in by itself, on purpose — getting it wrong once would teach Scan Finder the wrong company and every later document from them would follow it. Once you confirm the name once, the app recognises them from then on. ON by default — you can turn it off here.
Only use a learned layout on documents that actually name that company
When Scan Finder learns a layout, it remembers a handful of words from the top of the page to recognise it again. On a document you send out yourself — a purchase order — the top of the page is your own name and address, and that same block is printed on nearly every document you receive, as the delivery address. So a layout learned from one of your own orders can recognise itself in everybody else’s paperwork, and stamp the wrong company on it with high confidence. With this on, a layout is only used on a document that mentions that company somewhere on the page. Anything else goes to you instead. On the test set this removed 17 documents labelled with the wrong sender, and recovered 17 reference numbers and dates that had been read off the wrong layout. ON by default — you can turn it off here.
Don’t fill fields marked “not on this layout”
A field you’ve hidden for a sender’s layout (Document Types → Field visibility, or the teach wizard) stays empty instead of being filled with something read from elsewhere on the page — and a wrong value already stored is cleared on the next reprocess. Values you typed in yourself are always kept.
Collect every value of a “List” field
A field typed as “List (several values)” — like serial numbers — is read by scanning the whole document for its label and collecting every occurrence (“NW-123; NW-456”). Also unlocks the List type in the field editor. Off: list-typed fields read like ordinary text fields.
A label you teach becomes the keyword for that field
When you teach a field and confirm its printed label (e.g. “Job Sheet No”), that label replaces the generic ones (like “Ref”) when reading documents that match the layout you taught it on. Off: taught labels only guide the position, and the generic keywords keep hunting too.
Don’t accept a taught reading that isn’t the right shape
When you teach Scan Finder where a value sits, it reads that spot on every later document from the same sender. If the layout shifts, that spot can land on the wrong thing — and the wrong thing still gets used, because a taught reading is trusted. With this on, a taught reading that doesn’t look like the field it belongs to (the word “Account” where an account number should be, or “L922.14” where a total should be) is set aside, and Scan Finder falls back to finding the value the usual way. Off by default.
Treat “Your Order” as the customer’s order number, not yours
On a document a supplier sends you, a line labelled “Your Order” or “Your PO” is your purchase-order number, not theirs — so it belongs in the customer order field rather than being read as the supplier’s own order number. With this on, those labels fill the right field. Off by default.
Keep the slashes and dashes printed inside a reference
Reference numbers are often printed with separators — PI/26/6000, OED/91377. Scan Finder removes a stray slash that the scanner invents inside a code, and that clean-up currently cannot tell an invented slash from a printed one, so a reference like the ones above is filed as PI266000. With this on, a code that splits neatly into parts keeps its separators, while a stray mark wedged into an unbroken code is still cleaned up. Off by default.
Recognise VAT numbers from outside the UK
Scan Finder currently only recognises UK VAT numbers, so an invoice from an Irish, German or French supplier leaves the VAT field empty — and if you type the number in yourself, you are warned that your correct value looks wrong. This adds the VAT formats used across the EU, Switzerland and Norway. Each country’s format is matched exactly rather than by a loose “two letters and some digits” rule, so scanning mistakes are still rejected. Turn this on if you buy from outside the UK. Off by default.
Straighten crooked scans before reading them
A page that went through the scanner slightly askew is read at an angle, and the boxes Scan Finder was taught drift off the values they were pointed at. This straightens each crooked page before reading it — the same thing the ∞ Straighten button does in Review, applied automatically as documents come in. Your filed file is never altered; only the reading is straightened. It also changes what gets filed without you looking at it, so treat it as a trade rather than a free improvement. Pages that are already straight, and documents that carry their own text, are skipped. Off by default, and not yet recommended — straightening can make a marginal scan read worse as easily as better, and that has not been proven either way on real paper.
Don't let a hidden working figure block a document from filing itself
To check that a document's totals add up, ScanFinder sometimes reads figures your document type has no field for — a subtotal or a VAT line on a form that only shows a grand total. Those working figures are never shown to you, never learned, and are thrown away the moment you confirm. Until now one of them could quietly stop a perfectly good document from filing itself, and because it isn't on your form there was nothing on screen to look at or clear. This lets those hidden figures out of the filing decision, while still holding back any document where one of them looks wrong. ON by default — you can turn it off here.
Read small reference/date print more clearly
Enlarges a tightly-cropped reference or date before reading it and drops an over-sharpen step, so small print (e.g. “PO-17039” misread as “»0-17039”) reads correctly. Only helps where it can, never changes a read it can't improve. Off by default.
Faster field reads (warm OCR helper)
Keeps a small OCR helper warm in the background so drawing a box around a value reads in a fraction of a second instead of a couple of seconds. Reads work either way — turn this off only if you ever notice extra background activity.
Faster single-document reprocessing (uses more CPU cores)
When you Reprocess or Straighten & Reprocess one document, spreads the work across several CPU cores so it finishes faster on a slower PC. The result is identical either way — this only changes the speed. Off by default.
Processing
Parallel document processing
Documents processed at once
How many documents ScanFinder may read at the same time. Higher values are faster on powerful PCs but use more CPU and memory.
Scan reading detail (OCR resolution)
How finely each page is read for text. High (300 DPI) is most accurate for genuine paper scans. Balanced (200) and Fast (150) read noticeably quicker and use far less memory — ideal when your documents are already low-resolution. Lower detail can miss very small print, so check accuracy after changing it.
Per-document safety timeout
If a single document ever gets stuck being read (a rare unreadable page), skip it after this long and carry on — it's marked as an error you can retry, so one bad file can't freeze a whole batch.
Reading formats
Date format (region)
How to read an ambiguous numeric date like 03/04/2026. Day-first is 3 April (UK, Europe, most of the world); Month-first is 4 March (US); ISO is year-first. Dates written with a month name, or where the day is over 12, are read correctly whichever you pick.
Number format (region)
How money amounts group thousands and mark the decimal. Amounts are stored in a standard form regardless, so this only affects how they're read from your documents.
Document separation
Split multi-document PDFs automatically
When a single PDF contains several separate documents (e.g. a batch of one-page alerts), ScanFinder files each as its own document. Conservative — a normal multi-page invoice is never split, and each part goes to Review before filing.
Recognise separator sheets
Split a scanned pile wherever a printed ScanFinder separator sheet appears — the sheet page is removed from the filed documents. Print sheets below, slot them between documents, and scan the lot as one batch. If a sheet can't be read, nothing is split — the batch just arrives as one document in Review.
Separator sheets are detected on manual Import only — not yet in the auto-import (watch) folder.
Print separator sheets
Creates a PDF pack of numbered sheets and opens it — print from your PDF viewer (double-sided if you can). Sheets are reusable; keep the pack by the scanner.
Printing
Enable document printing
Adds a Print button in Review. It opens your printer's own dialog so you choose the tray, sides, paper and copies your printer supports — nothing is printed until you confirm there. Every print is recorded in the audit log.
Unrecognised documents
File unrecognised documents as General Documents
When ScanFinder can't tell what kind of document something is, it becomes a "General Document" — reviewed as usual, filed under a General folder, and found later by searching its text. Never applies to anything ScanFinder recognises, and these documents never file themselves automatically.
Suggest a title from the document's own heading
General Documents get a suggested Title picked from the page's main heading ("Boiler Service Certificate") — editable at review, searchable, and usable in filenames. If no clean heading is found the Title is simply left blank.
Name checks
Flag odd company/customer names for review
When a Supplier or Customer name reads like a document heading, a reference/code, OCR garble, or a cut-off name, ScanFinder marks it for review instead of filing it silently. It only flags for a human to check — it never changes or deletes the value.
Flag likely supplier misreads for review
When the letterhead at the top of the page names a different known supplier than the one ScanFinder detected, the document is sent to Review with a note — instead of being filed silently. Flag-only: it never changes the value or auto-corrects.

Keyword Label Overrides

Teach the keyword stage extra words to look for on the page for a field, so it's detected on import without per-document teaching.

How this works

For example, if a worksheet prints “Serial No.” next to the value you want in the Reference field, add it here once and every future worksheet picks it up.

On reprocessing, Scan Finder looks for your words first, then falls back to its built-in words if yours aren't on the page (built-in words are kept as a fallback, not removed). This applies to all documents of that type, not just the one on screen. A field you've taught with a drawn anchor still wins over these words. The extra words you add are saved on this computer only.

What's included & safety

Includes document types, fields, templates & mappings, file-naming, folders, and learned data (anchors, hints, corrections, logos). It does not contain your documents, users, or login details. Keep the password safe — without it the backup cannot be opened.

Restore overwrites your current document types, templates and learned data with the backup's; app settings are merged. This cannot be undone — export a backup first if unsure.
