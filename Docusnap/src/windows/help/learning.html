User Guide

Use this page when the same company keeps coming up wrong — a misspelt name that won't go away, or details that land in the wrong box again and again.

When it keeps getting a sender wrong

Scan Finder learns from every document you confirm. That's usually what makes it better — but if a wrong value was confirmed once, it can be learned too. This page is how you see what it has learned, and put it right. Start with the gentlest fix.

First: just correct and confirm

One wrong reading isn't a pattern. Fix the value in Review and confirm — a few correct confirmations usually outweigh a bad one. If the app itself offers "Apply to N & re-read" when you fix a sender's name, take it: that repairs the other waiting documents in one click. Come back here only when the same mistake keeps returning.

See what it has learned

Settings → Learning holds the Learned memory inventory — a read-only, click-to-browse view of everything Scan Finder remembers, sender by sender: the values, spellings and positions. Nothing here changes anything; it's for looking. If a sender's list contains a wrong spelling or a value that shouldn't be there, move to the next section.

In the Review window there's a closer tool: the ⚙ button's Learning history shows the values learned for one detail, where each came from (with an Open in Review link), and a Fix likely slips helper that spots a value one character off from the rest of its column.

Learning Repair — send the bad example back

The important thing to know: Scan Finder learns from the documents you have confirmed. So the real fix is to find the wrongly-confirmed document and un-confirm it — not to delete anything.

  1. Open Settings → Learning Repair and pick the sender (and kind of document).
  2. Look at its list — documents that "might not belong" or whose "data looks off" are flagged for you, with a preview.
  3. For a bad one, click Send back to Review. It returns to the queue; fix it there and confirm it properly. For a good one, Looks fine ✓.

How you know it worked: after the corrected document is re-confirmed, the wrong value drops out of the memory inventory, and the next document from that sender reads right.

The bigger levers (still safe)
  • Start fresh with this sender… — sets a sender's learning aside and begins again from your next confirmations. There's an Undo start fresh.
  • Forget learning for this type — the same, for a whole kind of document. It takes a backup first.

Nothing in Learning Repair deletes a document.

Teach it an extra printed word

If a sender labels a detail unusually — the worksheet prints "Serial No." where you want the Reference — add that wording once under Settings → Learning → Keyword Label Overrides and Scan Finder looks for it from then on. (Teaching the document with a drawn box does this for you; the overrides list is where you can see and manage those words.)

A different problem?

If the sender is simply new and everything is blank, that's not repair — teach it once: Teach your documents. If a document filed under the wrong company, see Put it back.
