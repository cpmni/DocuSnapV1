## ⭐ START HERE — THE VALIDATED MODEL (do not re-derive; full detail in
`memory/project_first_batch_filing_model_20260818.md`)
Why a first batch didn't auto-file, traced to the line and then PROVEN by prediction:
1. `docTrustGate`'s sub-100 path verifies each valued field against the scope's LEARNED FORMAT. A
   format group stays provisional — invisible to the gate — until `learning.FORMAT_SOLID_MIN` (=3)
   documents **carrying a value** exist for that (supplier, type, field).
2. A per-document-unique REFERENCE classifies as `'constant'` while the scope has ≤2 distinct
   values, so every new correct reference then fails literal equality. Clears at the 3rd DISTINCT.
3. **A taught document contributed NOTHING**: the confirm-upsert fires only from the CORRECTIONS
   loop and the teach sends `corrections: []`, while `getFieldFormats` reads `FROM extractions`.
   9/10 taught docs had no issuer row. So "confirm 3" was really "confirm 3 MORE".
**PROOF:** predicted that one more Meadowvale confirm would drop both walls at once — owner
confirmed one, **all 17 released**, queue 53 → 2. Round 9 then measured the fix: **2 further
confirms per sender instead of 3**, on 9 of 10 senders.

**Three dead ends — do not repeat:** "company names classify as freetext so can never verify" is
FALSE (`classifyLearnedShape` returns `'constant'` for a single-value scope, which verifies by
literal equality — Oracle SEND BACK). Verifying a `template_fixed` value against the template's own
frozen value is CIRCULAR (refused one layer down). Counting confirmed DOCUMENTS instead of the
format group's `confirmed_count` produces a header that LIES (3 docs, 2 values).

## ⏭ NEXT TASK — THE P1/PI CLASS FIX (owner's design, 2026-08-19; NOT built)
Round 9: **15 of 40 Pelican invoice numbers still read `P1/` or `PL/` where the page prints `PI/`**
(all caught, none misfiled — but 15 typed corrections).

**Why the shipped P arm (`ref_prefix_confusable_adopt`) did not fire — measured in the r9 DB:**
- It only inspects the **rawwitness** note class (`_rawwitness` in method AND "one character
  differs" in the note). Of six sampled misreads, only THREE were that class. The others were
  `template_mapping_padcodeflag` ("A wider reading of this box shows 'PI/25/6157'…") and the
  Gate-C class ("'P1/26/3318' doesn't appear on this page as written") — neither is looked at.
- **The correct value is already in the database in every sampled case**: three carry
  `corrected_to = 'PI/…'`, two name the right value inside the note text, and **the page text
  itself reads `PI/` on five of the six** (doc 0014's stored value is `P1/26/3318` while its page
  reads `PI/26/3318`).
- Its dominance bar (≥5 confirmed, ≥0.90 share) is also unlikely to be met early in a fresh install.

**THE OWNER'S DESIGN (his words, tidied):** *"If enough docs exist to confirm it is always PI, then
accept it — or even ask once, 'are all these PI?'. After ONE click to confirm, the system updates
the other documents automatically. It should NOT then ask 'do you wish to update the other 12?' —
if the user has already told us it is correct, there is no need for a second dialog."*

**Recommended shape to put to reggie → gary → Oracle:**
- **Trigger:** an operator CORRECTION on a ref-role field where (a) the change is a single
  confusable-class substitution in the PREFIX region, (b) the suffix is byte-identical, (c) the
  corrected prefix equals the scope's dominant/known confirmed prefix.
- **Action:** apply the SAME substitution to every still-**QUEUED** document in that (supplier,
  type) whose stored ref carries the same wrong prefix. Stamp provenance (`+prefix_class_fix`).
- **Consent model — act, then tell, with undo** (this is what the owner is asking for, and it is
  the Gmail/undo pattern barry cited): no dialog beforehand, a toast afterwards — *"Also corrected
  12 other Pelican invoices that read P1/ — see them / undo"*.
- **Safety rails to specify:** queued documents only (never a filed one); same scope + type; the
  substitution must be in the pinned confusable class table (`engine._PREFIX_CONFUSE_CLASSES`);
  suffix untouched; never the identity field; and prefer/record that a page witness agrees (most
  already do — see the measurement above).
- **The seam Oracle will press on:** this is a HUMAN-licensed class correction, not history
  rewriting a page — which is exactly the distinction that made him refuse "history alone NEVER
  rewrites" for the P arm. Brief him on that difference explicitly, and on the fact that the
  corrected documents remain in Review (the human still confirms them, or they auto-file only via
  the normal gate).
- **Cheaper adjacent win to consider first:** extend the P arm to the `padcodeflag` and Gate-C note
  classes, where the right value is already sitting in `corrected_to` or in the note text.
